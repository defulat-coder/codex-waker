状态定义：

- `verified`：当前本地实现已经过 Ego Lite 真实浏览器流程验证，并有页面状态、网络/控制台或持久化回读证据。
- `implemented`：当前代码与自动化测试已覆盖主要本地语义，但尚无完整 Ego Lite 流程证据，或浏览器证据未覆盖全部分支。
- `partial`：只实现了旧版能力的一部分；未实现部分仍影响该行完整语义，不能按完成宣称。
- `degraded`：以明确标识的本地替代或禁用状态承接专有云、企业服务或外部 provider 能力，不伪造成功。
- `excluded`：经范围决策明确不实现，且不属于本地成功主路径。

状态按整行能力判定：即使其中一个动作已通过验收，只要同一行仍包含未实现的关键语义，该行仍标为 `partial`。自动化测试全绿只证明被测试的合同，不自动提升为 `verified`。

## Circle 结论

对恢复源码检索后，未发现产品级 `Circle` 类、数据模型、接口或前端抽象。命中的 `circle` 均为 SVG `<circle>`、圆形头像、上传组件 `picture-circle`、CSS radial-gradient 等表现层词汇。因此本项目将“本地 Circle 类”解释为本地 SQLite 数据层是合理的。

本地落地命名应以 `database`、`repository`、`knowledge store` 或项目最终确定的 SQLite 抽象为准，不应为了兼容一个没有旧版证据的名字额外创建 `Circle`。如果后续获得新的原始源码或产品文档证明 Circle 是业务概念，再补 ADR 和适配层。

## 明确偏差原则

1. QMind 云知识库改为本地 SQLite + FTS5 + 可替换向量适配器，保留 notebook/source/binding/引用的用户语义。
2. Qoder 模型与会话运行时改为服务端 `@openai/codex-sdk` Thread API，Web 不直接接触 SDK、CLI 或凭据。
3. 企业 IM、远程员工、Aone/DWS、云分享、多用户 Public Projects、计划/Usage 与自更新可以降级，但页面必须说明原因、影响和可用替代。
4. 任何 `degraded` 项不能用假数据表现为真实外部连接成功；演示模式必须带明确标识。
5. P0 全部和 P1 的本地可实现部分完成自动化与 Ego Lite 验证前，不能宣称旧版主要前端已复刻完成。
