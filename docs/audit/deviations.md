# QoderWake 0.4.2 本地复现覆盖与偏差

本文件记录截至 2026-08-29 Goal 5 的最终工作区覆盖审计，对照 [`legacy-0.4.2-feature-matrix.md`](./legacy-0.4.2-feature-matrix.md) 判断已覆盖、部分覆盖和明确降级的范围。

判断规则：

- **已实现且验证**：当前代码存在，并有自动化测试或 Ego Lite 的交互与持久化回读证据。
- **部分实现**：主数据模型和可用流程已存在，但旧版的高级操作、视觉表达或外部集成没有完整复现。
- **降级/排除**：旧版能力依赖 Qoder/QMind 云、企业账号或远程基础设施；本地版本提供明确替代或不可用说明，不伪造成功状态。

权威浏览器证据为 [`docs/validation/ego-lite-2026-08-28.md`](../validation/ego-lite-2026-08-28.md) 的分 Goal 验收。Goal 5 使用 task space `9` 在 PC 桌面验证 Workflow；Goal 6 已在 PC 桌面验证 Board Lanes、真实 Workflow Human Action 与 Skill 上传/回读/冲突/删除，并完成全仓门禁。

## 结论

当前仓库已经形成可本地运行和验证的 TypeScript Waker 工作台。核心链路不再只是数据层或占位页面：Codex Thread 流式对话与恢复、项目上下文、附件进入 SDK turn、Session outputs、停止生成、本地 Knowledge、Memory、Automation 运行历史、Workflow 版本化编排与真实执行、Board 的真实 Task 投影/时间线、工作区共享 Skills、Connectors、Permissions、Human Actions 和 Waker 生命周期均有 UI、API、持久化与分 Goal Ego Lite 证据。

它仍不是旧版所有云端功能的逐项复制。真实企业 IM、远程员工、多用户云共享、QMind 云、Aone/DWS、self-update 和 Web 自建 HITL approvals bridge 被明确降级或排除；Workflow 提供只读路径图而非可视化节点编辑器，Board 不实现多人 assignee/group 协作，Skills 不提供自演化/version rollback，Mermaid/代码高亮与 Automation 外部 API/Event/Webhook source 仍未达到旧版完整度。
